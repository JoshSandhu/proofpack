## 1. What landed

**`src/proofpack/stats/discrimination.py`** — numpy + stdlib only, no scipy anywhere
(normal quantile from `statistics.NormalDist`, normal tail from `math.erfc`).

- `auroc_mann_whitney(scores, positives)` — AUROC by the Mann–Whitney statistic with
  **midranks** for ties. This is the day-1 H01 function, *moved* here; `gates.py` now
  re-exports it (`gates.auroc_mann_whitney` is unchanged for callers, so all 51 day-1 tests
  still pass unmodified). Aliased as `auroc`.
- `delong_covariance(score_matrix, positives)` — DeLong 1988 structural components via the
  **Sun & Xu 2014** O(N log N) midrank formulation, written from the algorithm (nothing
  vendored, so R2 §10's licence question never arises). Handles k classifiers at once and
  returns `(aucs, S)` where `S` is the full k×k covariance matrix. `delong_variance()` is
  the single-classifier wrapper.
- `wald_ci` and `logit_ci`. `auroc_number()` picks the **logit** interval as primary when
  `AUC > 0.9` or either class has < 30 cases (D1 §3.1), Wald otherwise, and always returns
  the other as `auroc_secondary`. A Wald interval that leaves [0,1] is clamped for rendering
  **and** flagged `wald_interval_exceeds_unit_range` so the clamp is visible, never silent.
- `paired_delong(a, b, positives)` — two correlated ROC curves on the same cases:
  `Var(A−B) = S_aa + S_bb − 2 S_ab`, a z statistic, a two-sided p-value, and a difference
  `Number` with a Wald interval on that variance.
- `roc_curve()` — `[[fpr, tpr, threshold], …]` from `(0,0,+inf)` to `(1,1,·)`, one point per
  distinct score. `locate_operating_points()` marks each declared operating point on it
  using the declared rule (`>=`, `>`, `<=`, `<`), not an assumed one.
- `DiscriminationResult` / `PairedDeLong` dataclasses matching `$defs.thresholdFree` in
  `output_schema_v1.json` (written yesterday; filled, not redesigned).

**Typed refusals, no silent fallbacks** — every one of these is a `Number` with no interval
and an explicit reason from the day-2 enum:
| situation | reason |
|---|---|

## 6. Open questions (≤5)

1. **Logit-vs-Wald primary rule.** D1 says logit when `AUC > 0.9` **or** class < 30. That
   means most subgroup tables will show logit and the overall table Wald — inconsistent
   within one document. Should the whole document use one rule (I'd argue: logit everywhere,
   Wald as the footnote) rather than switching per row?
2. **Clamping.** The secondary Wald interval is clamped to [0,1] and flagged. Alternative:
   print `1.1036` unclamped so the reader sees why it is not primary. Which does an FDA
   reviewer prefer?
3. **Small-class DeLong.** Today 5/5 gets a DeLong interval plus `very_low_precision`.
   After day 4, should DeLong be *refused* below 10 per class (R2 §1.3 reads that way) or
   shown alongside the bootstrap?
4. **Tie handling in `roc_curve`.** One point per distinct score, no intermediate-point
   dropping (unlike sklearn's default). Good for a rendered plot; it makes the array longer
   for large n. Cap the emitted array (e.g. 2000 points, thinning only collinear ones) before
   this reaches the JSON document?
5. **Paired DeLong difference interval.** Wald on `Var(A−B)`, which can cross ±1 at tiny n.
   A logit-type transform for a *difference* is not standard. Leave as Wald, or bootstrap it
   on day 4 for consistency?

## 7. Hardening pass (same day, after the adversarial verification)

The independent verifier (`handoffs/2026-09-09_E_verify.md`) recomputed **every** statistic from
first principles — Wilson, Clopper–Pearson, Newcombe method 10, AUROC and the DeLong SE all agreed
to machine precision (worst deviation 2.2e-16 against a 1e-4 acceptance line), and the 2000-resample
bootstrap agreed with the analytic DeLong SE to two significant figures. **No wrong number was
found.** No statistical method was changed in this pass. The three non-blocking items it raised are
now closed:

1. **`Number` is frozen.** `@dataclass(frozen=True)` in `src/proofpack/stats/number.py`. The
   "no Number without a CI or a typed reason" invariant is enforced in `__post_init__`, so a mutable
   dataclass let a caller strip `ci_lo`/`ci_hi` off an already-validated object; only the JSON schema
   caught that, and only if the document was validated. Assignment now raises
   `dataclasses.FrozenInstanceError`. Nothing relied on mutation: the sole in-place write is
   `with_precision_flags()` appending to the `flags` list, which frozen still allows and which cannot
   violate the invariant (flags are advisory). Tests:
   `tests/test_invariants.py::test_number_is_frozen_and_cannot_lose_its_interval` (asserts
   `ci_lo`, `ci_hi`, `est` and `method` all refuse assignment),
   `test_number_dataclass_is_declared_frozen` (catches a future edit that drops `frozen=True`), and
   `test_precision_flags_still_work_on_a_frozen_number`.

2. **CI runs every day's marker, and unmarked tests cannot hide.** The `-m day1` step in
   `.github/workflows/ci.yml` is replaced by a loop that reads the `dayN` markers out of
   `[tool.pytest.ini_options].markers` in `pyproject.toml` and runs each one; exit code 5 (a declared
   day with no tests yet, day4–day10 today) is tolerated, any other non-zero fails the job. So
   declaring `dayN` is all it takes to gate day N — there is no list to grow. The complementary half
   is `tests/conftest.py`, which records at collection time (before `-m` deselection, `tryfirst`) any
   test carrying no `dayN` marker, and
   `tests/test_invariants.py::test_every_collected_test_carries_a_day_marker`, which fails if that
   list is non-empty. A future day's tests therefore cannot be invisible to the per-day gate whether
   they are mismarked or unmarked. `test_ci_runs_every_declared_day_marker_without_a_hardcoded_list`
   asserts the workflow contains no literal `-m dayN` step. Both guards were confirmed to fail on
   purpose (a temporary unmarked test file failed the day-1 run).

3. **The F14 `[unverified]` marking is protected by construction, not vacuously.**
   `tests/test_invariants.py` extracts every method-10/method-11 interval bound from
   `fixtures/newcombe_table2.json` (both the unpaired and the paired blocks, formatted to the 4 dp a
   document would print) and checks, for every `.py`/`.j2`/`.jinja`/`.md`/`.html`/`.txt`/`.rst`/
   `.tex` file under `src/`, `templates/`, `design/` and `schema/`, that no file prints one of those
   values without also carrying the `[unverified` marking. Today that is still a clean sweep because
   no renderer exists — so the guard function is *also* exercised against a synthetic renderer
   string in `test_the_guard_itself_catches_an_unmarked_renderer` (an unmarked line is flagged; the
   same line plus "[unverified against the primary PDF]" is not), which makes the check real now
   rather than accidental. Verified by temporarily inserting `0.0524 to 0.3339` into a source file:
   the test failed, naming the file and both values. `test_the_fixture_is_not_packaged_into_the_wheel`
   keeps the fixture test-only. When the day-5 document templates land they inherit this guard with
   no further work; if a template legitimately needs to show a Table II value, it must carry the
   provenance status through to the rendered text.

**R2's printed logit bound is a truncation — do not "fix" the engine to match it.** R2 §9 prints the
F3 AUC logit lower bound as `0.3748`. The correct value is `0.37485775` (`0.3748577491715779`), which
*rounds* to `0.3749`; R2's figure is the true value truncated at 4 dp, not a different number. The
engine returns `0.374857749171578` and is **correct**; the independent verifier reproduced
`0.3748577491715779` from scratch and measured the engine's delta as 1e-16. The F3 test's 1e-4
tolerance absorbs the |Δ| = 5.8e-5 gap to R2's printed figure. Nobody should change the engine, the
test, or the fixture to match the document: the document is what is imprecise. Two consequences for
later days: whoever reconciles R2's printed tables against engine output should expect this
difference and leave it alone, and the renderer must **round** rather than truncate when printing
intervals to 4 dp.
