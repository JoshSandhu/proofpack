# Handoff — 2026-09-10 — Lane E (engine) — E4 "Bootstrap and clustered path"

## 1. What landed

**`src/proofpack/stats/bootstrap.py`** — numpy + stdlib only. No scipy anywhere, no
network, no LLM, nothing new in the dependency list.

**The resamplers.**
- `stratified_by_outcome(positives)` — rows resampled *within outcome class*, so every
  resample keeps the prevalence exactly.
- `clustered_by_case(positives, cluster_ids)` — cases resampled within outcome class;
  every row of a drawn case travels with it. A case whose rows carry both outcomes
  (one patient, several lesions) gets its own `mixed` stratum rather than being forced
  into one class.
- `clustered_flat(cluster_ids)` — one stratum, for a proportion inside a cell that is
  already conditioned on the outcome.
- Both kinds consume the generator identically — one `rng.integers(0, m, m)` per
  stratum, in stratum order. That is deliberate and it is what makes F9a exact (below):
  a clustered resampler over one-row cases reproduces a stratified one bit for bit.
  Cases are ordered by **first appearance**, not by sorted id, so renaming a customer's
  `case_id` values changes nothing.

**Percentile intervals.** `bootstrap_percentile(statistic, resampler, rng, B, level)`
returns a `BootstrapDraw` (the resample distribution, the interval, the resample sd,
the count of usable draws, and a typed reason when no interval was formed). Three
refusals, none of them silent: fewer than two units in a stratum →
`insufficient_clusters`; fewer than 90 % of the draws usable → `degenerate_resamples`
(the survivors are *not* an interval); zero-width interval → `boundary_estimate`
(a printed `(1.00, 1.00)` would claim a certainty the data do not support).

**The clustered auto-switch — objection X2.** `plan_clustering(unit, case_ids, n_rows)`
returns a `ClusterPlan` with a `route`:
| route | trigger | result |
|---|---|---|
| `declared` | `clustering.unit: case_id` in `criteria.yaml` | cluster bootstrap |
| `detected` | declaration says `none` but `case_id` values repeat | cluster bootstrap **and** `Finding("W13")` |
| `none` | one row per case, or no `case_id` | analytic interval |

Both routes produce **identical numbers**; only the provenance differs, and a test
asserts that. A declared `case_id` unit with no `case_id` column raises rather than
quietly degrading to row resampling.

**The refusal is a value, not a log line.** Every cell returns a `CellCI` carrying:
- `number` — the rendered `Number`. Under clustering its `method` is
  `cluster_bootstrap_percentile` and it carries the flag `delong_refused_clustered`
  (AUROC) or `wilson_refused_clustered` (proportion);
- `analytic` — a companion `Number` with **no interval** and the typed reason
  `clustered_data_analytic_ci_invalid`;
- `analytic_status` — a closed enum: `used | refused_clustered |
  replaced_small_class | unavailable`.

`CellCI.as_dict()` serialises all of it, round-trips through `json.dumps`, and every
`Number` it emits validates against `schema/output_schema_v1.json`. A test asserts all
three.

**Per-cell routing.** `auroc_ci(...)`: clustered → cluster bootstrap, DeLong refused;
i.i.d. with both classes ≥ 10 → DeLong exactly as day 3 computes it, **no bootstrap at
all** (R2 §1.5: never bootstrap where the analytic form is standard); i.i.d. with a
class below 10 → stratified bootstrap as the rendered interval (R2 §1.3), the DeLong
Number carried alongside as `analytic`, and the switch recorded both in `method` and in
the new flag `analytic_ci_replaced_small_class`. `proportion_ci(...)`: Wilson unchanged
when i.i.d. (a test asserts it equals day 2's `proportion()` on F1), cluster bootstrap
with Wilson refused when clustered.

**Seed policy, written down and tested.**
- B = 2000 default; `bootstrap.B` may raise it.
- One run seed: `bootstrap.seed` if declared, else `20240101`. `BootstrapPolicy.as_dict()`
  records `seed_source: declared | engine_default` (and the same for B), so the manifest
  can never imply the customer chose a seed they did not choose.
- **Every cell derives its own generator** from `(run_seed, cell_key)` via
  `default_rng([seed, blake2b(cell_key)])`. Two consequences, both tested: adding a
  subgroup cannot move an unrelated subgroup's interval, and the derivation survives a
  new process (`hashlib.blake2b`, never the built-in `hash()`, which is salted per
  process). A test runs the same computation in two subprocesses under different
  `PYTHONHASHSEED` values and asserts byte-identical JSON.
- No global RNG anywhere. The test that proves it parses `src/proofpack` with `ast` and
  rejects any `np.random.*` / `random.*` attribute other than `default_rng` — grepping
  was not enough, because the module's own prose says "never call `numpy.random.seed`".

**New closed-enum values** (code and `schema/output_schema_v1.json`, kept in sync by a
test that compares all three enums as sets):
- reasons: `insufficient_clusters`, `degenerate_resamples`;
- flags: `delong_refused_clustered`, `wilson_refused_clustered`,
  `analytic_ci_replaced_small_class`.

`Number` itself is untouched and still `frozen=True`.

**The F3 acceptance criterion, honestly.** The brief asked that "the bootstrap
reproduces the DeLong AUROC confidence interval within a stated tolerance on the F3
fixture cohort", with the tolerance justified from Monte-Carlo error at B = 2000. Here
is what is actually true, in three parts.

*(a) The pinned interval is exact.* R2 §9 records `(0.44, 1.00)`; the engine returns
`(0.44, 1.00)` at B = 2000 with `default_rng(20240101)`, and the same value under four
different quantile conventions (the endpoints sit on support points). This pins the
resampling scheme, which is the part that could silently be wrong.

*(b) The endpoint tolerance holds on F3, and only on F3.* The tolerance was derived
before measuring: the Monte-Carlo standard error of a percentile endpoint is
`sqrt(p(1-p)/B)·sd/φ(z)` = `0.0598·sd`, floored by half the AUROC's support spacing
`1/(n_pos·n_neg)` where the bootstrap distribution is that coarse; the tolerance is
three of those. On F3 that gives **τ = 0.0600** (the grid term, 0.02, dominates), and a
separate test confirms the model by measuring the endpoint spread over twelve seeds
(0.0198 observed against 0.02 predicted). Measured against the DeLong Wald interval as
the engine renders it, `(0.4964, 1.0000)` — clamped from 1.1036 and flagged — the gaps
are **0.0564 and 0.0000**, worst 0.0564 over thirteen seeds, inside τ.

  **It does not generalise, and I did not pretend otherwise.** A percentile interval is
  asymmetric and bounded; a Wald interval is symmetric. Once the AUROC moves away from
  0.5 the two differ systematically rather than by Monte-Carlo noise. At 60 cases per
  class and AUROC 0.85 the gap is 0.00722 against τ = 0.00617 — 3.5 Monte-Carlo standard
  errors. `test_the_endpoint_tolerance_is_not_claimed_beyond_f3` asserts that failure so
  the F3 result can never be quietly generalised. On F3 itself the same is true against
  the **logit** interval `(0.3749, 0.9639)`, which D1 §3.1 makes primary below 30 per
  class: gaps 0.0651 and 0.0361, the first outside τ. That is asserted too.

*(c) What does hold everywhere is the variance.* The bootstrap standard deviation
reproduces the DeLong standard error to within `3/sqrt(2B) + 1/n_min` — three relative
Monte-Carlo standard errors of a sample sd, plus the leading O(1/n) bias of a bootstrap
variance estimate for a two-sample U-statistic. Checked over a 7 × 4 × 3 grid (5, 10,
20, 30, 60, 100, 200 per class × four separations × three cohort seeds). On F3:
0.14842 against 0.15492, −4.2 %, band 24.7 %. At 100 per class: −1.3 %, band 5.7 %.
This is the claim that would actually catch a broken resampler — drawing rows instead
of cases moves the standard error by a factor of √(rows per case).

  One grid cell is excluded and it is named in the code: 10 per class at AUROC 0.99,
  where the ratio is +15.8 % against a 14.7 % band. The band's `1/n` term is the leading
  term of an expansion that assumes a **non-degenerate** U-statistic, and at AUROC 0.99
  the AUROC is degenerate — which is the same regime where D1 already switches to the
  logit interval and where the engine refuses an interval outright at exactly 0 or 1.
  `NON_DEGENERATE_AUC = 0.98` in the test file, with that reasoning.

**F9 is met in both halves, and stronger than the register asks.**
- *D1 §3.2 register half* — "cluster-bootstrap CI on duplicated data equals F3
  stratified-bootstrap CI within 0.01 (same cases, same seed)". It is **exactly** equal:
  the two resamplers draw the same integers in the same order, so all 2000 resample
  values are identical, element for element.
- *Variance-inflation half* — with k rows per case and complete within-case correlation
  the design effect is k, so the clustered interval should be about √k wider. Measured
  over three cohort seeds: k = 3 → 1.748, 1.772, 1.854 (√3 = 1.732); k = 5 → 2.255,
  2.261, 2.350 (√5 = 2.236). Asserted as a ±20 % band around √k, which is far outside
  the ~3 % Monte-Carlo noise on an interval width at B = 2000.
- *A fixture with a real, partial correlation*, because duplicated rows are the easy
  case. Cases carry a case-level effect of variance ρ plus per-row noise of variance
  1−ρ, so the design effect is 1 + (k−1)ρ. At k = 4, measured width ratios: ρ = 0 →
  0.974, 0.994, 1.035 (predicted 1.000); ρ = 0.3 → 1.302–1.338 (1.378); ρ = 0.6 →
  1.581–1.639 (1.673); ρ = 0.9 → 1.812–1.919 (1.924). **The ρ = 0 row is the important
  one**: with independent rows the cluster bootstrap does *not* inflate anything, so the
  module is not simply widening every clustered interval regardless of the data.
- The premise of the refusal is measured too: duplicating each row k times divides the
  naive DeLong SE by √k to within 6 %, at k = 2, 4 and 9.

**A decision you should know about.** Under clustering the **point estimate is
unchanged** — a clustered AUROC or proportion is still computed over all analysed rows,
so it equals the number the customer would get from their own table, and cases with
more rows carry more weight. Weighting every case equally is a different estimand, and
picking one for the customer would be a vendor-set analysis decision. Recorded in the
module docstring; open question 3 below.

## 6. Open questions (≤5)

1. **Clustered point estimate.** Row-weighted (what I built, matching the customer's own
   table) or case-weighted (equal weight per patient)? A reviewer looking at a
   multi-lesion study might expect the latter. I will not choose this for a customer;
   if it should be declarable, it needs a field in `criteria.yaml`.
2. **Detected clustering — warning or HALT?** Today `case_id` repeats with
   `clustering.unit: none` produce `W13` and a cluster bootstrap. The stricter reading is
   that the customer's declaration is simply wrong and the run should HALT until they
   fix it. Which does the design partner's first pack want?
3. **The AUROC discreteness floor.** The endpoint tolerance uses half the AUROC support
   spacing as a floor. That is defensible and it matched the measured spread at 5 vs 5
   to two decimal places, but it is my model, not a published one. Worth one paragraph
   in T7, or leave it as a test-only construct?
4. **B for subgroup tables.** B = 2000 per cell × ~40 subgroup cells × several metrics is
   a few hundred thousand resamples per run. Acceptable on a laptop, possibly not under
   Pyodide (S-day 6 measures load time, not compute). Should the demo declare a lower B
   and say so on the page, rather than the customer's runs being slowed to match?
5. **`degenerate_resamples` threshold.** I refuse an interval when fewer than 90 % of
   draws yield a defined statistic. Stratification makes that essentially unreachable
   for AUROC and proportions, so the number is currently arbitrary and untested against
   real data. Keep 90 %, or refuse on *any* degenerate draw?
