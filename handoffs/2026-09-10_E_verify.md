## 2. The eleven blockers deduplicate to seven defects. All seven are fixed.

Two of them were found independently by all three lenses, which is the reason to keep
three.

### D1 — `cluster_ids` supplied with `plan` omitted handed clustered rows to DeLong and Wilson
*(safety B1, acceptance B1 — the day's headline safety property, defeated)*

`_resolved()` fabricated an i.i.d. plan whenever `plan is None`, **without ever looking
at `cluster_ids`**. The mirror mistake — clustered plan, missing ids — has always raised
and has its own test. This direction returned a DeLong interval 2.1× to 4.6× too narrow
on fully clustered data, with `analytic_status: used`, no `delong_refused_clustered`
flag, no companion refusal and no W13. Reachable from the exact day-5 call shape the
handoff prescribes: both arguments are keyword-optional, so it is a one-token slip on
one cell out of forty, with no runtime signal.

**Fix.** `_resolved` now takes the ids and is symmetric in all three directions: no plan
plus repeating ids → the `detected` route (cluster bootstrap, refusals, W13 available);
no plan plus unique ids → i.i.d. as before; a plan positively asserting independence over
repeating ids → `ValueError`, a contradiction, exactly as the mirror case is.

**Regression test** `test_cluster_ids_without_a_plan_never_reach_delong_or_wilson`.
Against `5bc69fb`: `AssertionError: assert 'used' != 'used'`.

### D2 — one mixed-outcome patient deleted a 200-patient AUROC interval
*(statistics B2, safety B3)*

`clustered_by_case` gives a case whose rows carry both outcomes its own `mixed` stratum —
the multi-lesion patient the module docstring names as the reason the stratum exists.
`bootstrap_percentile` then refused the whole cell when **any** stratum had fewer than
two units, and `very_low_precision` was attached when any stratum had fewer than ten. So
200 patients × 2 lesions with exactly *one* mixed patient returned no interval at all,
with `not_estimable_reason: insufficient_clusters` printed beside `n_cases: 200` and a
`very_low_precision` flag on a 400-row study. Two mixed patients and it computed
normally — an arbitrary cliff at exactly one. Over simulated multi-lesion cohorts,
19/200 refused at N=40 and 67/200 flagged `very_low_precision` at N=100.

**Fix.** The floor now applies to the **class**, counted over the cell: a mixed case
carries rows of both outcomes so it counts towards both (`Resampler.class_units`), and
a singleton stratum contributes deterministically rather than vetoing the cell. The
precision tier is taken from the cell's case count, not from the smallest stratum.

**Measured, not assumed.** `scratchpad/coverage_check.py` and
`scratchpad/singleton_coverage.py`, against an independently written pooled cluster
bootstrap:

```
true lesion-level AUROC ~ 0.76004 (K=3, rho=0.6); reps=400 B=500; MC se ~ 0.0109
N= 40  engine: coverage 0.930 over 400 formed, 0 refused | pooled oracle 0.940
N=100  engine: coverage 0.950 over 400 formed, 0 refused | pooled oracle 0.950

200 patients x 2 lesions, exactly one mixed (reps=200, MC se 0.0154):
mixed=1: engine coverage 0.945 over 200 formed, 0 refused | pooled oracle 0.945
mixed=3: engine coverage 0.960 over 200 formed, 0 refused | pooled oracle 0.950
```

The pre-repair engine scored 0.901 over 474 formed with 26 refused at N=40 and 0.930 at
N=100 (statistics note §B2). The repair refuses nothing, loses no coverage, and lands on
the independent oracle within Monte-Carlo error.

**Regression test** `test_one_mixed_outcome_case_does_not_veto_a_two_hundred_case_cohort`.
Against `5bc69fb`: `AssertionError: insufficient_clusters`.

### D3 — the typed refusal named the wrong class
*(statistics B2 second half, acceptance B4, safety N1)*

`insufficient_positives` was returned whenever the smaller stratum was short, whichever
class it was, so a Number read `n_pos: 25, n_neg: 1, insufficient_positives` — false on
its face, and it points the customer at the wrong column. `insufficient_negatives` had
been in the enum since day 2 and was emitted by no code path.

**Fix.** `_refusal_reason` chooses from the class that is actually short. Under
clustering the shortage is of independent **cases**, so `insufficient_clusters` is kept
there (saying "insufficient positives" beside `n_pos: 199` would be the same lie), and
the enum comment in `number.py` now says what the reason means.

**Regression test** `test_the_refusal_names_the_class_that_is_actually_short`. Against
`5bc69fb`: `assert 'insufficient_positives' == 'insufficient_negatives'`.

### D4 — a shipped v1 Number promised a bootstrap that had already landed
*(statistics B3)*

A perfectly separated cell (AUROC exactly 1, routine in a subgroup table) returned the
day-3 Number carrying `ci_pending_bootstrap` — defined in `number.py` as "day-4 bootstrap
will fill this interval" — with `analytic_status: used`, defined as "the analytic
interval is the rendered one", when there is no interval at all. Two false statements
into the structured output and therefore into the document.

**Fix.** `auroc_ci` returns `analytic_status="unavailable"` (already in the enum, emitted
by nothing) when the analytic Number has no interval. `ci_pending_bootstrap` is gone from
both day-3 AUROC branches: the bootstrap cannot help at perfect separation either (every
resample gives 1.0, refused as `boundary_estimate`), so there is no later interval to
promise. It survives **only** on F1 and MCC, where the promise is still live and waiting
on your day-2 question 1; the enum comment now says exactly that.

**Regression test**
`test_a_perfectly_separated_cell_promises_no_bootstrap_and_claims_no_analytic_ci`.
Against `5bc69fb`: `assert 'ci_pending_bootstrap' not in ['ci_pending_bootstrap']`.

### D5 — every clustered Number reported the run's case count, not the cell's
*(statistics B1, acceptance B3)*

`n_cases=cplan.n_units` read the **run-level** `ClusterPlan`, and §4 of the handoff tells
day 5 to build one plan for the run and pass it to every cell. A 36-row subgroup slice
therefore printed `n_cases: 40` beside `n_pos: 18, n_neg: 18` — more cases than rows,
arithmetically impossible, in the subgroup table a customer hands to a regulator. Not
one of the 85 day-4 tests could see it: every fixture made the cell the whole cohort, and
the statistics verifier's mutation M5 (substituting the *correct* value) left all 85
passing.

**Fix.** `n_cases = resampler.n_units`, on the rendered and the companion Number.

**Regression test** `test_n_cases_is_the_cells_own_case_count_not_the_runs`, which also
asserts `n_cases <= n_pos + n_neg`. Against `5bc69fb`: `assert 40 == 12`.

### D6 — the clustering detection rule was pinned by no test
*(safety B2)*

D1 line 43 is "`n_rows > n_cases` triggers clustered path" — any duplication, no
threshold. HEAD implemented exactly that and nothing tested it: the safety verifier
replaced `units < n_rows` with `units * 2 < n_rows` and **all 213 tests passed**, while
100 patients of whom 10 contribute a second lesion silently moved from a cluster
bootstrap with W13 to a plain DeLong interval. Every day-4 fixture duplicated *every*
case, so partial clustering — the realistic shape — was never exercised.

**Fix.** No code change was needed; the code was right and undefended.
`test_any_repeated_case_id_triggers_the_clustered_path`, parametrised at 1, 2 and 10
duplicated ids out of 100, asserts the route, the counts, the W13 finding and that the
routed cell's method is `cluster_bootstrap_percentile`. Proved in a worktree at
`5bc69fb` with the mutation applied: all three parametrisations fail with
`assert (False, 'none') == (True, 'detected')`.

### D7 — `clustered_flat` accepted misaligned `cluster_ids`
*(safety B4, acceptance B2, statistics N4)*

`clustered_by_case` has always checked the length; `clustered_flat`, which the clustered
*proportion* path uses, did not. `cluster_ids` shorter than the cell produced one Number
built from three different row sets — estimate over all 400 rows, interval resampled from
the first 200, `n = 400` — with no exception and no flag, indistinguishable from the
correct output. The AUROC path raises on the identical caller error, so the engine's own
"raise rather than quietly degrade" doctrine was applied in one direction only.

**Fix.** `clustered_flat(cluster_ids, n_rows=None)` validates when the length is given,
and `proportion_ci` gives it.

**Regression test** `test_a_clustered_proportion_refuses_cluster_ids_that_do_not_align`.
Against `5bc69fb`: `Failed: DID NOT RAISE ValueError`.
