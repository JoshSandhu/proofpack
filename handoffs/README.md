# Handoff notes

One note per build session, named `YYYY-MM-DD_<lane>.md` (lane E = engine).
Written by the session at the end of its day; read by Josh in the evening and
by the next session at the start of its day.

Each note contains, in this order:

1. **What landed** - files, modules, tests, with the exact test command and its
   pasted summary line.
2. **What was cut and why** - anything from the day's brief that was deferred,
   with the day it moves to.
3. **Acceptance line** - the brief's acceptance statement and whether it is
   demonstrably true; if not, the shortfall.
4. **What tomorrow needs** - the first thing the next session should read or do.
5. **Needs from Josh** - people-track items that block or unblock the engine.
6. **Open questions** - at most five, each answerable in a sentence.

Rules: no `[unverified]` number is presented as fact; no regulatory section
numbers are typed by a session (they come from Josh's transcription into
`design/guidance_map_v1.csv`); nothing in a note quotes customer data.
